# 通用非功能性检测清单（General Checklist）

> code-review skill 的检测清单之一，配合 [`project-checklist.md`](./project-checklist.md) 使用。
> 改编自通用 nfr-checklist，已适配本项目（A 股股票系统：Java stock-watcher + Python stock-engine + Thymeleaf 前端）。
> 关注"代码扛不扛得住"——即非功能性质量维度。

## 如何使用本清单（智能裁剪）

**不要每次都跑完全部 150+ 项。** 先根据本次变更涉及的模块/语言，按下表「适用范围」确定需要检查的章节，只检查相关章节。**未检查的章节必须在评审报告里注明「未检查 + 原因」**，禁止静默跳过——静默跳过会让报告看起来"全通过"，这是对评审结论的污染。

| 变更范围 | 必查章节                                     |
|---|------------------------------------------|
| 任何后端代码（Java / Python） | 一性能、三事务、四异常、五并发、六幂等、十日志、十一API、十二配置、十三可维护性 |
| 涉及数据库 / SQL | 一·1.1 数据库查询、三事务、七数据库                     |
| 涉及缓存（Caffeine / Redis） | 二缓存（全查）                                  |
| 涉及数据爬取 / Tushare 拉取 | 数据爬取/Tushare 专项见 project-checklist E 组；本清单查 六幂等 I-02 |
| 涉及前端（Thymeleaf / JS / ECharts） | 十四前端专项（全查）                               |
| 涉及外部调用 / 第三方（watcher↔engine HTTP） | 四异常 E-01~E-06、十日志 L-05                   |
| 涉及鉴权 / 敏感数据 / 账户 | 九安全（全查）                                  |

> 判定数据库相关项时，**必须先查 `stock-watcher/src/main/resources/schema-mysql.sql`** 确认表结构与索引，勿凭记忆。

## 评级标准
- ✅ 通过：代码已正确处理
- ❌ 不通过：存在明确问题（严重 = 必须修复；建议 = 建议修复）
- ⚠️ 风险：当前可接受但存在隐患，建议优化
- ➖ 不适用：本次变更不涉及此项

## 一、性能（Performance）

### 1.1 数据库查询性能

| # | 检查项 | 判定标准 | 级别 |
|---|--------|---------|------|
| P-01 | 是否存在 N+1 查询 | 循环内执行数据库查询 → ❌ | 严重 |
| P-02 | 列表查询是否有分页 | 无 LIMIT 的全表查询 → ❌ | 严重 |
| P-03 | WHERE 条件字段是否有索引 | 高频查询条件无索引 → ❌ | 严重 |
| P-04 | 是否存在 SELECT * | 查询了不需要的字段 → ⚠️ | 建议 |
| P-05 | 大表 JOIN 是否合理 | 超过 3 表 JOIN 或笛卡尔积风险 → ⚠️ | 建议 |
| P-06 | 是否存在慢查询风险 | 单条 SQL 预估执行时间 > 1s → ❌ | 严重 |
| P-07 | 批量操作是否使用 batch | 循环中逐条 INSERT/UPDATE → ❌（见项目专项 PJ-07） | 严重 |
| P-08 | 是否存在锁表风险 | 大事务中持有行锁/表锁时间过长 → ❌ | 严重 |

### 1.2 接口响应性能

| # | 检查项 | 判定标准 | 级别 |
|---|--------|---------|----|
| P-09 | 核心接口是否有响应时间目标 | 列表接口 P99 > 500ms 未优化 → ⚠️ | 建议 |
| P-10 | 是否有不必要的串行调用 | 多个无依赖的外部调用（如 watcher→engine）串行执行 → ⚠️ | 建议 |
| P-11 | 大数据量计算是否异步化 | 同步计算耗时 > 3s 的任务 → ❌ | 严重 |
| P-12 | 是否存在重复计算 | 同一请求内相同数据被计算多次 → ⚠️ | 建议 |
| P-13 | 返回数据量是否合理 | 单次返回超过 1000 条记录未分页 → ❌ | 严重 |

### 1.3 内存与资源

| # | 检查项 | 判定标准 | 级别 |
|---|--------|---------|------|
| P-14 | 是否存在内存泄漏风险 | 大对象未释放、监听器未注销、连接未关闭 → ❌ | 严重 |
| P-15 | 大文件/大数据集是否流式处理 | 一次性加载全部数据到内存 → ❌ | 严重 |
| P-16 | 是否有资源池配置 | 数据库连接池、HTTP 连接池未配置上限 → ⚠️ | 建议 |

## 二、缓存（Caching）

| # | 检查项           | 判定标准 | 级别 |
|---|---------------|---------|------|
| C-01 | 高频读取数据是否有缓存   | 同一数据被频繁查询（>10次/分钟）但无缓存 → ⚠️ | 建议 |
| C-02 | 缓存 TTL 是否合理   | 股票行情数据缓存 > 5 分钟 → ⚠️（数据时效性） | 建议 |
| C-03 | 缓存失效策略是否明确    | 数据更新后缓存未主动失效 → ❌ | 严重 |
| C-04 | 是否有缓存穿透防护     | 查询不存在的数据会每次都打到 DB → ⚠️ | 建议 |
| C-05 | 是否有缓存击穿防护     | 热点 key 过期瞬间大量请求打到 DB → ⚠️ | 建议 |
| C-06 | 是否有缓存雪崩防护     | 大量 key 同时过期 → ⚠️ | 建议 |
| C-07 | 缓存与 DB 一致性方案  | 先更新 DB 还是先删缓存？是否有明确策略 → ⚠️ | 建议 |
| C-08 | 缓存 key 设计是否规范 | key 是否有统一前缀、是否包含版本号、是否有过期时间 → ⚠️ | 建议 |
| C-09 | 缓存数据大小是否合理    | 单个 value > 1MB → ⚠️ | 建议 |

## 三、事务与数据一致性（Transaction & Consistency）

| # | 检查项 | 判定标准 | 级别 |
|---|--------|---------|------|
| T-01 | 多表写入是否使用事务 | 涉及 2 张以上表的写操作无事务保护 → ❌ | 严重 |
| T-02 | 事务粒度是否合理 | 事务中包含外部调用（HTTP/RPC，如 watcher↔engine）→ ❌ | 严重 |
| T-03 | 事务中是否有耗时操作 | 事务内执行 > 1s 的操作（如大批量计算）→ ❌ | 严重 |
| T-04 | 失败时是否有回滚/补偿 | 部分成功部分失败时无处理逻辑 → ❌ | 严重 |
| T-05 | 分布式场景一致性方案 | 跨服务/跨库写入无最终一致性方案 → ⚠️ | 建议 |
| T-06 | 乐观锁/悲观锁使用是否合理 | 高并发更新场景无锁保护 → ⚠️ | 建议 |
| T-07 | 数据状态机是否完整 | 状态流转是否有非法跳转的可能 → ⚠️ | 建议 |

## 四、异常处理与容错（Error Handling & Resilience）

| # | 检查项 | 判定标准 | 级别 |
|---|--------|---------|------|
| E-01 | 外部依赖调用是否有 try-catch | 调用第三方 API/engine/Tushare 无异常捕获 → ❌ | 严重 |
| E-02 | 异常是否被静默吞掉 | catch 块为空或仅打印日志无后续处理 → ❌ | 严重 |
| E-03 | 是否有合理的重试机制 | 网络调用无重试，或重试无退避策略 → ⚠️ | 建议 |
| E-04 | 重试是否有上限 | 无限重试或重试次数 > 5 次 → ⚠️ | 建议 |
| E-05 | 是否有降级/兜底方案 | 核心依赖不可用时系统完全不可用 → ⚠️ | 建议 |
| E-06 | 是否有熔断机制 | 外部服务持续失败时仍不断调用 → ⚠️ | 建议 |
| E-07 | 错误信息是否对用户友好 | 将堆栈信息/内部错误码直接返回前端 → ❌ | 严重 |
| E-08 | 是否有全局异常处理 | 未捕获的异常导致 500 白屏 → ❌ | 严重 |
| E-09 | 部分失败场景是否处理 | 批量操作中部分成功部分失败，无明确处理 → ⚠️ | 建议 |

## 五、并发与线程安全（Concurrency）

| # | 检查项 | 判定标准 | 级别 |
|---|--------|---------|------|
| CC-01 | 共享可变状态是否有保护 | 多线程访问共享变量无锁 → ❌ | 严重 |
| CC-02 | 是否存在竞态条件 | 先读后写（check-then-act）无原子保护 → ❌ | 严重 |
| CC-03 | 定时任务是否有防重入 | 上一次未执行完，下一次又触发 → ⚠️ | 建议 |
| CC-04 | 接口是否有防重复提交 | 用户快速连续点击导致重复写入 → ⚠️ | 建议 |
| CC-05 | 异步任务是否有并发控制 | 无限制地创建异步任务/线程 → ⚠️ | 建议 |
| CC-06 | 数据库操作是否考虑并发 | 先 SELECT 再 UPDATE 无 WHERE 条件校验 → ⚠️ | 建议 |

## 六、幂等性（Idempotency）

| # | 检查项 | 判定标准 | 级别 |
|---|--------|---------|------|
| I-01 | 写接口是否幂等 | 相同请求重复调用产生不同结果 → ❌ | 严重 |
| I-02 | 数据爬取是否幂等 | 重复爬取同一数据导致重复插入 → ❌ | 严重 |
| I-03 | 是否有唯一约束防重 | 业务唯一键无数据库唯一索引 → ⚠️ | 建议 |
| I-04 | 更新操作是否幂等 | 使用 `SET count = count + 1` 而非 `SET count = 目标值`（导致重复累加）→ ⚠️ | 建议 |

## 七、数据库设计与操作（Database）

| # | 检查项 | 判定标准 | 级别 |
|---|--------|---------|------|
| DB-01 | 表是否有主键 | 无主键或主键设计不合理 → ❌ | 严重 |
| DB-02 | 是否有合理的索引 | 高频查询条件无索引 → ❌ | 严重 |
| DB-03 | 是否有冗余索引 | 多个索引覆盖相同字段 → ⚠️ | 建议 |
| DB-04 | 字段类型是否合理 | 用 VARCHAR 存数字、用 TEXT 存短字符串 → ⚠️ | 建议 |
| DB-05 | 是否有 created_at / updated_at | 缺少审计字段 → ⚠️ | 建议 |
| DB-06 | 大字段是否分离 | TEXT/BLOB 字段与高频查询字段在同一张表 → ⚠️ | 建议 |
| DB-07 | 是否有数据归档策略 | 历史数据无限增长无清理方案 → ⚠️ | 建议 |
| DB-08 | 删除操作是否为软删除 | 物理删除导致数据不可恢复 → ⚠️ | 建议 |
| DB-09 | 批量操作是否分批次 | 一次性操作 > 10000 条记录 → ⚠️ | 建议 |
| DB-10 | 是否有 SQL 注入风险 | 拼接 SQL 而非参数化查询 → ❌ | 严重 |

## 九、安全（Security）

| # | 检查项         | 判定标准 | 级别 |
|---|-------------|---------|------|
| S-01 | 接口是否有鉴权     | 敏感接口无 token/session 校验 → ❌ | 严重 |
| S-02 | 是否有权限校验     | 用户可访问/操作不属于自己的数据 → ❌ | 严重 |
| S-03 | 敏感数据是否脱敏    | 日志/响应中暴露完整手机号、身份证等 → ❌ | 严重 |
| S-04 | 是否有接口限流     | 无限流保护，可被恶意刷接口 → ⚠️ | 建议 |
| S-05 | 输入是否校验      | 用户输入未做长度/格式/范围校验 → ⚠️ | 建议 |
| S-06 | 是否有 XSS 防护  | 用户输入直接渲染到页面 → ⚠️ | 建议 |
| S-07 | 密码/密钥是否硬编码  | 代码中明文存储密码、API Key、Tushare token → ❌ | 严重 |
| S-08 | CORS 配置是否合理 | 允许所有来源（`*`）→ ⚠️ | 建议 |

## 十、日志与可观测性（Logging & Observability）

| # | 检查项 | 判定标准 | 级别 |
|---|--------|---------|------|
| L-01 | 关键操作是否有日志 | 数据写入/删除/状态变更无日志 → ⚠️ | 建议 |
| L-02 | 日志级别是否合理 | 正常流程用 ERROR 级别、异常用 INFO 级别 → ⚠️ | 建议 |
| L-03 | 日志是否包含上下文 | 日志无法定位到具体请求/用户/数据 → ⚠️ | 建议 |
| L-04 | 是否有敏感信息泄露 | 日志中打印完整请求体（含密码/token/Tushare token）→ ❌ | 严重 |
| L-05 | 外部调用是否记录耗时 | 排查性能瓶颈（watcher↔engine、Tushare 调用）→ ⚠️ | 建议 |
| L-06 | 异常日志是否包含堆栈 | 仅记录 message 无 stacktrace → ⚠️ | 建议 |
| L-07 | 是否有请求链路追踪 | 跨模块调用无法串联 → ⚠️ | 建议 |

## 十一、API 设计规范（API Design）

| # | 检查项 | 判定标准 | 级别 |
|---|--------|---------|------|
| A-01 | 响应格式是否统一 | 不同接口返回结构不一致（未用 ApiResponse）→ ⚠️ | 建议 |
| A-02 | 错误码是否规范 | 所有错误都返回 500 或无错误码 → ⚠️ | 建议 |
| A-03 | 是否有版本管理 | 接口变更可能影响已有调用方 → ⚠️ | 建议 |
| A-04 | 分页参数是否统一 | 不同接口分页参数命名/格式不一致 → ⚠️ | 建议 |
| A-05 | 是否有请求参数校验 | 非法参数导致服务端异常而非 400 → ⚠️ | 建议 |
| A-06 | 接口命名是否 RESTful | 命名混乱（如 /getData、/fetchList）→ ⚠️ | 建议 |
| A-07 | 是否有接口文档 | 新增/修改接口无文档更新 → ⚠️ | 建议 |

## 十四、前端专项（Frontend Specific）

> ⚡ 仅涉及前端代码（Thymeleaf 模板 / JS / ECharts）变更时检查。

| # | 检查项 | 判定标准 | 级别 |
|---|--------|---------|------|
| F-01 | 是否有 loading 状态 | 数据请求期间页面无任何反馈 → ⚠️ | 建议 |
| F-02 | 是否有空状态处理 | 数据为空时页面空白或报错 → ⚠️ | 建议 |
| F-03 | 是否有错误状态处理 | 请求失败时页面无提示或白屏 → ❌ | 严重 |
| F-04 | 列表是否有虚拟滚动 | 渲染 > 100 条 DOM 节点未做虚拟化 → ⚠️ | 建议 |
| F-05 | 是否有防抖/节流 | 搜索框/滚动事件无防抖节流 → ⚠️ | 建议 |
| F-06 | 组件卸载是否清理 | 定时器/事件监听/请求未在 unmount 时清理 → ❌ | 严重 |
| F-07 | 是否有 key 属性 | 列表渲染无唯一 key → ⚠️ | 建议 |
| F-08 | 响应式适配 | 仅考虑单一分辨率 → ⚠️ | 建议 |
| F-09 | 数字格式化 | 金额/涨跌幅未格式化（如 0.123456789）→ ⚠️ | 建议 |
| F-10 | 涨跌颜色是否统一 | 涨红跌绿（或项目约定）是否全局一致 → ⚠️ | 建议 |
